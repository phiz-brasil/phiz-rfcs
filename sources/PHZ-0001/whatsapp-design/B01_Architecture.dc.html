How a business message reaches the user: Company → BSP → Meta Cloud API → WhatsApp → User
Outbound path, and how replies and statuses come back (webhooks)
⓪ OPT-IN
Prerequisite for everything below: Ana has authorized PicPay to message her on WhatsApp (flow O). The company checks its consent record (O5) for the right category before calling the BSP. No opt-in → the message should never be sent.
① Company
PicPay back-end
CRM / service platform (e.g. Salesforce) decides who gets what: payment alert, bill, campaign — only for users with a valid opt-in.
→
② BSP
Blip / Zenvia / Twilio / Infobip
Connects the company to Meta: account onboarding, templates, agent inbox, chatbots, billing. Most large Brazilian companies use one.
→
③ Meta Cloud API
graph.facebook.com
Meta-hosted API. Checks permissions, template, 24h window and marketing limits; returns a message ID (wamid).
→
④ WhatsApp network
End-to-end encrypted delivery
Same delivery network as personal chats. Queued while the phone is offline.
→
⑤ User's phone
Ana's WhatsApp
Push notification → business chat in the inbox → opens the chat (flow C).
←
Return path (webhooks): user replies, button taps, form submissions and statuses (sent / delivered / read / failed) go from Meta to the BSP and on to the company. Opt-in answers (O4) and opt-outs (D10) also come back this way and must update the consent record.
←
One-time setup
1. Create a WABA (WhatsApp Business Account) in Meta Business Manager; verify the business.
2. Register the company phone number → Phone Number ID; display name ("PicPay") is reviewed by Meta.
3. Submit message templates (text, variables, buttons) for Meta approval.
4. BSP gets an access token and configures the webhook URL.
Per-message sequence
0. Company checks: active opt-in for this category?
1. Company asks the BSP: "send template pix_received to 5511987654321".
2. BSP calls POST /{Phone-Number-ID}/messages (B3).
3. Meta returns a wamid = accepted, not yet delivered.
4. Webhooks: sent → delivered → read (B4); replies drive flow D.
Mapping to PhizChat
Company (PicPay) → middleware (Salesforce-like / BSP) → PhizChat Open Platform API (replaces Meta Cloud API) → PhizChat network → PhizChat user. MVP scope: business account authentication + sending messages. Consent (opt-in) handling should be part of the design from day one.
