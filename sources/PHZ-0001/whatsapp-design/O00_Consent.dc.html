No opt-in, no message
The consent lifecycle every business message depends on
!
Before a company may send a WhatsApp message that the user did not ask for, the user must have authorized that company: clearly told they will receive its messages, with the company's name stated (Meta policy). Mentioning WhatsApp and one choice per purpose are best practices. Having the phone number is not enough — and Meta does not verify any of this (O6).
1 · COLLECT
The user says yes
In the company's app (O1), at sign-up or checkout (O2), by messaging the company first (O3), or by answering yes inside WhatsApp (O4).
↓
2 · RECORD
The company stores proof
Who, when, where, which wording, which message categories (O5). Required by Meta's policy and Brazil's data protection law (LGPD).
↓
3 · SEND
Only within what was authorized
Payment alerts consent ≠ marketing consent. Messages go out through the BSP and Cloud API (flow B) and land on the phone (flow C).
↓
4 · REVOKE
The user can withdraw at any time
Stop offers (D7), block and report (D8), reply a stop keyword (D10), or switch off the toggle in the app (O1). The company must honor it immediately.
Counts as opt-in
✓ Clear notice naming the company, actively accepted (best: unticked box that also names WhatsApp)
✓ Separate choice per message type (alerts vs. offers)
✓ User sends the first message — for that conversation
✓ User taps "Yes" to an in-chat question
Does not count
✗ Pre-ticked boxes or consent hidden in long terms
✗ Number in the CRM from another context
✗ Number collected for another purpose, with no notice
✗ Purchased or shared contact lists
